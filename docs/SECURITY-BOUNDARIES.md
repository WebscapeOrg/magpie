# Security boundaries

Required before changing network requests, credentials, subprocesses, resource loading or reviewing an affected security boundary.

- Trace attacker-controlled bytes through decoding, normalization, interpolation and the final consumer. Include mail headers/bodies, MIME names, server responses, URLs, credentials and persisted settings. Base64 is transport, not sanitization.
- Gmail destinations are fixed by the backend. Reject unsupported provider/account/source values before credential lookup or network dispatch. Stored unsupported data must not be converted into Google identities or removed automatically.
- Sender-controlled requests require checked public DNS answers and connections pinned to those addresses, retaining TLS verification for the original hostname. Name checks (`Html.isPublicHost`) or a lookup followed by independent resolution do not suffice. `scripts/public_http.py` enforces this; no production fallback or environment bypass may weaken it.
- Keep credentials out of argv, logs, world-readable settings and attacker-selected origins. Google refresh tokens reach the typed credential boundary without entering process arguments. OAuth client files are 0600, not plugin settings (`shell.json` is world-readable). Apply `OAuth.redact` before credential-bearing errors reach labels.
- Every network request needs a deadline. QML `XMLHttpRequest` has no working `timeout`/`ontimeout`; use a Timer calling `abort()`, whose DONE/status-0 callback must finish/decrement the request exactly once.
- QML requests follow redirects automatically. One-click unsubscribe uses `scripts/unsubscribe.py`, which never redirects or interpolates sender data into shell/curl config. Treat 3xx as refusal, not another destination.
- Message resource attributes and attachment paths remain security boundaries regardless of appearance preferences. Follow [message rendering](MESSAGE-RENDERING.md); never give original remote image URLs to Qt. Render sender-written labels as plain text and remove line breaks from outgoing header values.
- Security tests must fail on the vulnerable behavior and assert no forbidden effect: process/network request, credential disclosure or file write. Cover sibling providers/callers, CR/LF/CRLF, trailing controls, NUL, malformed encodings and valid quotes/backslashes/Unicode/multiline bodies. Use controlled targets and synthetic credentials.
- Report tested versions and environment gaps. Distinguish confirmed exploits, demonstrated boundary violations and unverified delivery hypotheses. Synthetic Gmail resources do not prove Gmail delivers those bytes; curl stubs do not prove real parsing/network behavior. State pre-existing limitations and the scope of a PASS; never claim a complete audit from a scoped fix.
