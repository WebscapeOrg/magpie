# Local mail and responsiveness (API 8)

The Gmail account keeps an account-owned local replica. Inbox lists, supported searches, labels, unread counts and saved message bodies can load without Gmail. Coverage is shown while mail downloads, so a partial search is never presented as a complete mailbox search. Spam, Trash, user labels and every inline plain-text/HTML body are included. Named file attachments download on demand and remain saved afterward. Existing provider limits on individual messages and attachments still apply.

## Storage and synchronization

`src/local_mail` owns one SQLite database per registered Gmail account beneath the platform state directory, at `omamail/mail/<SHA-256 of account ID>/`. SQLite 3.51.3 or newer is required. The custom VFS accepts only the database and its journal/WAL filenames relative to a pinned private directory. It refuses links, arbitrary attached paths and unsafe ownership. An exclusive owner lease protects one writer and two readers; WAL uses FULL synchronization and private process memory for shared-memory pages. A second process uses the authenticated owner IPC endpoint instead of opening SQLite itself.

Content-addressed JSON blobs live below the same directory. Reads verify their digest and message identity. SQL stores summaries, effective labels, FTS5 text, sync coverage, retry jobs and edit intents. The existing bounded resource cache is imported incrementally without replacing newer local resources. Replica bodies and retained attachments are durable data, outside the legacy disposable cache quota. New body and attachment storage requires 1 GiB of remaining space plus the new payload size. Existing saved mail remains readable when storage is low.

A persisted Gmail history checkpoint is taken before inventory. Inventory includes Spam and Trash, saves page tokens and generations, and resumes after restart. History pages commit queued work, deletions and the next checkpoint in one transaction. Repeated or malformed pagination is refused. Expired history starts a new inventory generation; old rows are removed only after inventory has finished and intervening history has been reconciled. Missing inline text remains an explicit, retryable job instead of silently completing coverage. Incomplete resources cannot suppress a foreground retry; opening one hydrates its missing text with interactive request priority. The worker shares per-message fetch locks with foreground reads and queued label edits. It reports changes at most once per second during successful downloads.

API 8 QML uses `local.watch`, `local.refresh` and `local.unwatch`; Gmail's earlier summary poll/preloader is disabled for those accounts. Other providers retain their existing native watches. The Gmail request scheduler, quota accounting and server retry delays continue to apply to all replica requests. The replica performs no send, read-marker or remote-image action merely to preload content.

## Search and mailbox edits

`local.list` returns summaries, a query-bound keyset cursor and coverage. A response also caps retained summary JSON at 16 MiB and returns a continuation rather than accumulating an unbounded page; an individually oversized row is refused. Supported operators are words, quoted phrases, trailing word prefixes, `OR`, negation, `from:`, `to:`, `cc:`, `subject:`, `filename:`, `label:`, supported `in:`/`is:` labels, `category:`, `has:attachment`, `before:` and `after:`. FTS5 handles Unicode body tokens; dates use local midnight. Spam and Trash are excluded unless explicitly included. This is a defined local subset of Gmail search: unsupported syntax returns `local_search_unsupported`, and **Search online** explicitly switches that query to Gmail.

FTS predicates use parameterized SQL. Selective matches use indexed result sets; very broad matches use row-constrained FTS checks while SQLite walks date order, avoiding materializing and sorting an entire mailbox merely to return its newest page.

`local.edit` freezes message IDs and persists label additions/removals under an idempotency ticket. UI reads use server labels plus pending intent. Repeated changes to one message coalesce to the final label state; later edits remain separate from an in-flight confirmation. Sync reads the current labels, applies any needed change and confirms the result before marking it done. Authentication/network failures leave edits pending. A deleted message or refused mutation becomes a visible conflict. Undo cancels a queued ticket before it is claimed; once started, the UI asks the user to use the opposite mailbox action. No arbitrary model text can supply a target account or send authorization.

## Reading, composition and calendar

The mailbox uses a recycled `ListView`; loaded summary count no longer determines the number of live row components. Ordinary provider summaries appear progressively. Avatars and overviews are enriched for the visible rows and their immediate neighbours. Reader body adoption precedes secondary metadata/model callbacks. The source and render caches each hold at most 32 entries, 12 per account and 64 MiB of serialized data: together at most 64 entries, 24 per account and 128 MiB. These are cache-payload limits, not total process RSS limits. One prefetch worker prepares up to two cached neighbours on each side without fetching remote images or marking them read.

API 8 compose sends structured fields to `outbox.compose` and `draft.compose`. Attachment imports return opaque handles scoped to the registered account and draft. Native code resolves those handles and builds MIME; file bytes need not make a round trip through QML. Attachment previews and exports fetch provider locators through the backend and reuse retained bytes. Recipient matching reuses an index until the contact set changes.

An explicit Send can authorize `resumeUnsent` for mail that has never started delivery. Such mail survives restart and waits for connectivity; Undo remains available. A preflight runs outside the outbox state lock and rechecks cancellation before delivery. The outbox persists `sending` before the send call. A process interruption during delivery becomes `unknown` and is never retried automatically. Legacy queued entries without this authorization still cancel on restart. Server draft saves and calendar/label management writes remain online operations.

Calendar list responses are parsed in Rust. XML/ICS input is bounded; document types are refused. Visible, bar and reminder controllers share source/range caches and coalesce identical native reads. At most two list requests run concurrently. Selecting a date range displays its cached events immediately; late replies may fill their own cache but cannot replace the selected view. Per-source request timestamps prevent stale responses from restoring deleted events. Adjacent ranges warm only while the calendar remains visible. Day indexes avoid repeatedly filtering every event for every visible day. Reminder checks remain every 60 seconds; bar checks remain every 10 minutes.

## Diagnostics and recovery

Gmail and RPC diagnostic producers enqueue into bounded channels without waiting for disk writes. Dedicated writers flush batches of up to 64 or every two seconds. Overflow/persistence failures increment dropped-record counters. RPC records contain only an allowlisted method, process/generated correlation numbers, queue and elapsed time, request size and success. Gmail records link to the originating RPC when available; background work has no caller correlation. Caller request IDs, account addresses, credentials, message IDs, subjects, bodies and raw server errors are excluded. Diagnostic report generation validates these records again and retains the existing private-file and report-size limits.

A failed local read does not delete or rebuild data. Keep the database, WAL, blobs and edit intents together for diagnosis. Do not delete the WAL, clear the owner lock, or open the database through another SQLite VFS while its owner is running. Automatic destructive rebuilds are deliberately absent because pending edits may be the only record of an offline action. Account removal and credential cleanup retain their existing explicit workflows.

## Verification

Run `make validate` in an environment that permits local sockets, DBus and the repository's private-directory checks. The focused suites cover search/paging, WAL restart recovery, edit coalescing/undo, malformed history rollback, storage link refusal, attachment-handle ownership, diagnostic redaction, native calendar parity, stale range responses, row recycling and keyboard Undo. Full provider/IPC/security tests require their controlled local servers; blocked setup is not a security pass.

Run the synthetic database benchmark with `MAGPIE_BENCH_MESSAGES=100000 cargo test --release --lib local_mail::tests::benchmark_local_queries -- --ignored --nocapture`; use `1000000` for the separate scale case. It measures database queries returning 50 summaries, not application startup or Gmail throughput. `python3 benchmarks/mail/ui_latency.py --output /tmp/magpie-paint.json` measures completed Qt frames for loaded-list navigation and prepared HTML. It excludes RPC, disk, network and compositor presentation. End-to-end startup, live-provider contention, HTTP/2/compression and release compiler comparisons require separate measurements before changing transport or release settings.
